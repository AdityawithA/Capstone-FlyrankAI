# How to Add the Next Case Study

Use this workflow every time a new project is ready.

## Step 1 — Choose the real work

Pick one finished piece of work that has enough evidence to discuss honestly:

- live/demo URL
- repository
- screenshots
- measurable outcome or useful shipped feature

## Step 2 — Write the three beats

Keep the case study short:

### Problem
What user/team problem existed?

### What I did
What did I personally build, decide, test, or ship?

### What came of it
What changed, shipped, improved, or was learned?

Avoid generic claims such as “built an amazing project.” Prefer concrete evidence.

## Step 3 — Add it to the portfolio

Find the portfolio's project/case-study collection and add:

- title
- one-line description
- three-beat story
- stack
- live URL
- GitHub URL
- representative image
- optional metrics

Reuse the portfolio's existing component and styling rather than creating a new page system.

## Step 4 — Verify

Run the portfolio locally and verify:

- desktop layout
- mobile layout
- keyboard navigation
- links
- images/alt text
- no console errors
- new case appears in the correct order

## Step 5 — Ship

Commit the change, deploy it, then open the production portfolio and verify the new case from a clean browser session.

## Step 6 — Keep the habit

When the next real project is finished, repeat this document instead of starting the portfolio process from zero.
