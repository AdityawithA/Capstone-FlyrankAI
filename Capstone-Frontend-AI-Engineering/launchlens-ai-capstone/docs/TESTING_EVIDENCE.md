# Testing Evidence

## Test strategy

The highest-risk frontend behaviors are:

1. Accessible form rendering.
2. Example input onboarding.
3. Successful AI response rendering.
4. Network/API failure feedback.

These are covered in `components/LaunchLens.test.tsx`.

### Run

```bash
npm test
```

Expected result: **4 tests passing**.

Also run:

```bash
npm run typecheck
npm run build
```

## Coverage target

The capstone asks for coverage of at least 50% of components. LaunchLens currently has one primary interactive component and a focused test suite covering its core states. For the final submission, run the project locally and record the actual coverage generated by the chosen test runner if your reviewer requires a numeric coverage artifact.

## Manual critical-flow test

**Flow:** idea → submit → loading → structured result

Expected:
- Submit button is disabled until the input reaches the minimum length.
- Loading state is announced through `role="status"` and `aria-busy`.
- Successful response renders a product title, problem, users, MVP, acceptance criteria, risks, and next step.
- Failed requests produce a visible `role="alert"`.
